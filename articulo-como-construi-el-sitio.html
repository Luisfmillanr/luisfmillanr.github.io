Artículo 03 · Desarrollo web

Cómo construí y publiqué este sitio web

Luis Fernando Millán Rivera Lectura: 6 min 2025

Este sitio fue construido como un proyecto web estático, usando HTML para definir la estructura, CSS para el diseño visual y GitHub Pages para publicarlo en línea de forma gratuita. En este artículo explico el proceso completo: desde la planificación del contenido hasta la publicación final.

Por dónde empezar: el contenido antes que el código

El error más común al construir un sitio web es empezar escribiendo código antes de saber qué va a decir el sitio. El resultado es un diseño bonito con textos de relleno que después hay que adaptar, muchas veces rompiendo lo que ya estaba hecho.

En este caso, el primer paso fue definir el mensaje central:

Consultor tecnológico enfocado en la mejora de procesos mediante soluciones digitales.

Con esa frase como brújula, se definió la estructura de páginas, el contenido de cada sección y los tres artículos antes de escribir una sola línea de HTML.

La estructura de archivos

Un sitio estático bien organizado tiene todos sus archivos en la raíz del repositorio, con nombres claros y sin espacios: 

luisfmillanr.github.io/
├── index.html
├── proyectos.html
├── articulos.html
├── contacto.html
├── articulo-procesos-tecnologia.html
├── articulo-procesos-manuales-digitales.html
├── articulo-como-construi-el-sitio.html
├── styles.css
├── app.js
└── assets/
    └── img/

Todo en la raíz porque GitHub Pages sirve el sitio desde ahí. Si los archivos HTML estuvieran en subcarpetas, las rutas relativas se complicarían sin necesidad.

HTML: estructura antes que presentación

HTML — HyperText Markup Language — es el lenguaje que define la estructura de una página web. No controla colores ni tamaños; solo describe qué es cada elemento: un título, un párrafo, una sección, un enlace.

La decisión más importante en HTML es usar las etiquetas correctas según su significado semántico. Por ejemplo:

  • <nav> para la barra de navegación
  • <main> para el contenido principal
  • <article> para contenido independiente como este
  • <section> para agrupar contenido temático
  • <footer> para el pie de página

Usar las etiquetas correctas mejora la accesibilidad, ayuda a los motores de búsqueda y hace el código más fácil de mantener.

CSS: diseño con variables y un solo archivo

CSS — Cascading Style Sheets — controla todo lo visual: colores, tipografía, espaciado, layout y adaptación a diferentes tamaños de pantalla.

Una de las decisiones más importantes fue usar variables CSS para todos los valores que se repiten: 

:root {
  --color-accent:  #0F766E;
  --font-display:  'Syne', sans-serif;
  --space-6:       1.5rem;
}

Esto permite cambiar el color de acento en un solo lugar y que el cambio se propague automáticamente a todo el sitio. Sin variables, habría que buscar y reemplazar en cientos de líneas.

Modo oscuro y claro

El sitio incluye soporte completo para modo oscuro y claro, con tres capas de lógica:

  1. Media query del sistema — detecta si el SO está en modo oscuro
  2. Clase body.dark — fuerza el modo oscuro manualmente
  3. Clase body.light — fuerza el modo claro aunque el sistema esté en oscuro

Diseño responsive

El sitio se adapta a móviles mediante media queries que reorganizan el layout cuando la pantalla es menor a 768px. Las grillas de tres columnas pasan a una columna, el menú se convierte en hamburguesa y los tamaños de fuente escalan con clamp().

JavaScript mínimo

El sitio usa JavaScript solo para dos funciones: el menú hamburguesa en móvil y el toggle de modo oscuro/claro. Todo el resto es HTML y CSS puro.

El archivo app.js se carga al final del <body>, no en el <head>. La razón es simple: el navegador lee el HTML de arriba hacia abajo. Si el script se ejecuta antes de que existan los botones que busca, falla en silencio.

Publicación en GitHub Pages

GitHub Pages permite publicar un sitio web estático directamente desde un repositorio de GitHub, de forma gratuita y con una URL en el formato usuario.github.io.

El proceso de publicación se reduce a tres comandos que se repiten cada vez que se hacen cambios: 

git add .
git commit -m "descripción del cambio"
git push origin main

Después de un push, GitHub Pages detecta los cambios automáticamente y publica la nueva versión en segundos.

Lo que aprendí en el proceso

Construir este sitio fue un ejercicio de tomar decisiones de diseño con criterio, no solo de escribir código que funcione. Las decisiones más importantes no fueron técnicas, sino de contenido y comunicación: qué decir, cómo estructurarlo y por qué cada sección existe.

La lección más valiosa: un sitio web no debe impresionar al developer que lo construyó, sino comunicar con claridad a quien lo visita.
